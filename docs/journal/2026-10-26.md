# October 26, 2026

## Engine: pool draw and level pools (#4)

- **Done by the AI**: `drawPools` (seeded snake draw, or a full random draw, both reproducible from a seed), `moveTeam` for manual corrections, `rankAcrossPools` (overall ranking across pools) and `buildLevelPools` (by rank, or by bands of a maximum size); a seeded random generator and a shared `EngineError` base with typed codes; example tests and property-based tests (every team drawn once, pool sizes differ by at most one, top seeds in different pools, level pools keep every team and never mix two teams from the same pool by rank, bands follow the overall ranking).
- **Taken over by hand**: Nicolas let the AI move ahead on the roadmap on its own, except for important product decisions.
- **Decisions**: unseeded teams are drawn after the seeds; bands are never larger than the pool size; teams at the same position in pools of different sizes are compared per match (recommended default, put to Nicolas as a choice).

## Engine: single elimination and full placement brackets (#5, part 1)

- **Done by the AI**: `singleElimination` (with an optional consolation bracket) and `fullPlacement`, built as matches whose sides are a team, a bye, or the winner or loser of an earlier match; `resolveBracket` advances them from played matches, and `bracketPlaces` gives the final places; example tests and property-based tests (every team of a full placement bracket gets a unique place from 1 to N, a single elimination crowns one champion and gives the byes to the top seeds, the consolation bracket only holds first-round losers).
- **Decisions**: standard seeding (1 and 2 can only meet in the final); byes fill the bracket up to the next power of 2 and go to the top seeds; teams knocked out in the same round share a place, with no match for 3rd place; the consolation bracket takes the first-round losers. Double elimination comes in a second PR.

## Engine: double elimination (#5, part 2)

- **Done by the AI**: `doubleElimination`, built on the same bracket matches as single elimination; a match can now be played only if an earlier match was won by a given side, which gives the grand final reset; example tests and a property-based test (every team but the finalists is out after exactly 2 losses, every team gets a place from 1 to N, the reset is played only when the losers bracket champion wins the first final).
- **Decisions**: winners bracket losers drop into the losers bracket in reverse order, which spares the second-round losers a rematch (a property-based check showed later rematches cannot always be avoided, so the specs only promise this); teams knocked out in the same losers bracket round share a place; a score with home and away swapped is refused, as the scoring table enters it on the bracket match.

## Engine: match scheduling on courts (#6)

- **Done by the AI**: `planSchedule` (greedy placement on courts, preferring rested teams), `adjustSchedule` (real times, delays and early ends), `moveMatch`, `removeCourt` and `assignReferees`; example tests and property-based tests (every match placed once, never two places at once for a team or a court, back-to-back matches only when no rested match was ready, a consistent schedule after random delays, a referee never plays or referees two matches at once).
- **Decisions**: times are minutes from an origin the app chooses, as the engine has no clock; a court never stays empty to avoid back-to-back matches; during the day matches keep their court and their order on it; starting earlier than planned is a setting; referees come from the same pool first, then the least used team.

## Engine: configuration validation (#12)

- **Done by the AI**: `validateTournament` and `validateMatchRules`, which return every faulty setting with a code, a message and its path; the schedule checks raised in the review of #17 (a match scheduled twice, a `from` that is not a number); example tests and property-based tests (every generated valid tournament and set of match rules passes, each mutation that breaks one rule is rejected with its code).
- **Decisions**: the validator collects every error instead of stopping at the first, so the organizer sees them all at once; qualification is followed from phase to phase; level pool qualification is left to when the pools exist. Typed engine errors were already added with #14, so the issue's note on error codes needed no change.

## App foundation (#8)

- **Done by the AI**: `apps/api` (NestJS 12, Prisma 7 with PostgreSQL, a first `tournaments` resource checked by `validateTournament`, a Socket.IO gateway that pushes new tournaments); `apps/web` (Next.js 16, Tailwind 4, a shadcn/ui button, French messages through next-intl, a web manifest and a service worker for installation); Dockerfiles and `docker-compose.yml`; a CI job that builds the images, starts the stack and checks the API and the web app answer. The API is tested end to end over HTTP and WebSocket with an in-memory database.
- **Decisions**: the VPS already runs Caddy, so the stack sits behind it instead of Traefik (the issue's wording), with ports bound to localhost; the draw seed is drawn by the API at creation, since the engine has no randomness; the API allows Prisma's install scripts (pnpm blocks them by default) so migrations run in the image; Biome keeps type-only imports off in the API, since Nest injects services by their runtime class, and leaves import extensions to the bundler in the web app. The database password has no default and lives only in `.env`, after GitGuardian flagged the defaults; a body the engine cannot read (a `null` team) is refused with a 400 rather than crashing.
